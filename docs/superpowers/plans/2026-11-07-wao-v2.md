# WAO 能力迭代 v2 — 实施计划（W1 MCP 网关 / W2 TUI / W3 资产系统）

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development。步骤用 `- [ ]` 跟踪。
> **Goal:** 三大能力：①AI Agent 经 MCP/Skill 直接操作公司 ②`wao tui` 运维仪表盘 ③平台资产系统（skill/memory/MCP/prompt/工具五类，共享/独享，含 RTK token 瘦身与代码检索装备）。
> **Architecture:** 沿用万物皆插件——MCP 网关是新插件（最小自研 MCP 子集，零新依赖）；TUI 是入口子命令（零依赖 ANSI 自绘）；资产系统扩展 provider 端口物化管线（统一 materialize 管线写入各家原生格式）。
> **Spec:** docs/DESIGN.md v3（存量权威）+ 本计划 W3 节（资产系统设计随 T0 细化并入 DESIGN）。
> 前情：主项目 M1-M3 已交付并生产运行（见 HANDOFF.md）。生产热更纪律不变：页面热生效；core-engine/插件改动后控制器 kickstart。

## Global Constraints

- 沿用主项目全部红线：TDD/两段审查/盲评（W1/W3 收尾各一场）/复制即契约/内核零改动（本迭代预计零内核改动——MCP 走插件路由、TUI 走入口装配层）
- 零新 npm 依赖（MCP 最小自研：JSON-RPC 2.0 + streamable HTTP 子集；TUI 用 node:readline+ANSI）

## Backlog：wao-hq 集团总部（云端控制面）— 仅记录，未启动

> 2026-11-07 需求拆解会话沉淀。**用户裁定暂不启动**；启动时走完整 brainstorm→spec 流程，本节仅存档结论防丢失。

- **动机**：WAO 客户端将多人多电脑安装，需要云端配套。
- **已澄清的形态结论**（若启动按此为起点）：
  - 架构方向选 A：各客户端装连接器插件 `hq-link`（middleware 型，requires core-engine）→ 单向心跳(60s)+HTTP 拉取；云端永不反向连接客户端、客户端零新增监听端口；部署=内网 Mac + tailnet 组网（不暴露公网）+ launchd 常驻。
  - 控制面：独立仓库 `wao-hq`，单 Node 进程、零 npm 依赖、JSON 文件存储；Web 看板沿用无构建 ESM 风格。
  - 鉴权：简单登录（admin/member 两角色，scrypt+HMAC 会话）+ 设备令牌（只显一次/仅存哈希/与 machineId 熔断绑定/可吊销）。
  - 完整版范围曾设计为：舰队监控（只看不动，bot 状态只报计数不报内容）+ 插件市场（下载解压到 WAO_PLUGINS_PATH 运营方目录，installMode 默认 manual，启停复用现有 API）+ 知识/模板库（类型注册表：persona/broadcast-copy/test-questions，增量同步落地 data/templates/）。
- **最新范围裁定（用户）**：嫌完整版复杂，**首期只做云端看板**（心跳上报+舰队状态可视化）；插件市场与模板库后议。
- 命名与界面文案均为占位（wao-hq/hq-link/总部看板等公司话词表），启动前需另过一遍。
